# 应用协议：用蒸馏模型分析现代问题

## 0. 加载档案

- 档案在 `distilled/<人物名>.md` 或用户指定路径：直接读，进入下文。
- 档案不存在、用户只要一个快速答案：内联轻量蒸馏（不落盘），仍须遵守引文纪律和盲区声明。内联卡按模板的节次结构（世界观/启发式/盲区）编号，便于用「第 X 节第 N 条」格式引用。
- 档案不存在、问题复杂或用户想要模型资产：建议先完整蒸馏，再回来分析。

## 1. 问题转译（先于一切分析）

把用户的现代问题翻译成该人物时代的等价问题。例："要不要裸辞去创业" → "弃官从商，可值当？"

- 能转译：继续。
- 不能转译（找不到他经验里的等价物，如植发、选显卡）：直说这个模型不适用，不要硬答。最多补一句"他能给的只有态度层面的参考"，并明确标注这是氛围感，不是他的判断。

## 2. 输出格式

### 他眼中的问题
用他的框架重述问题，不是复述用户的框架。

### 他的拆解
点名调用档案第 2/3 节的条目（写作"第 2 节·随处安顿"这样的引用），逐步推理。

### 他会做
3 个具体动作，每个动作后括注依据：（史据：<哪段经历/哪条原文>）。

### 他会警告
调用第 4 节盲区，指出用户当前方案里最可能翻车的点。

### 局限声明
一句话说清本分析中哪些是历史类比、哪些只是氛围感；涉及重大现实决策时提醒咨询现实中的专业意见。

## 3. 写作纪律

- 每个论断都能回溯到档案条目或史据；档案中标「存疑」/「伪托」的金句不得作为论据。
- 默认第三人称叙述（"王阳明会……"）。用户明确要求第一人称扮演对话时才切换，切换后也只演绎他的思维方式与已证实的态度，不虚构史实性台词、不编造经历。
- 结尾始终提醒：人物模型提供的是视角而非决策，决定权在用户。
