# ZCode Skills 合集

个人自建的 Agent Skills 合集,沉淀自媒体账号运营与思维工具的完整工作流。每个 skill 遵循开放的 Agent Skills 格式(`SKILL.md` + `references/`),主流 coding agent 均可安装。

## 一览

| Skill | 一句话用途 |
|---|---|
| [account-niche-finder](#account-niche-finder--账号定位分析) | 对话式定位:我适合用 AI 做什么账号 |
| [account-doctor](#account-doctor--账号诊断医生) | 用真实数据给抖音/小红书账号做体检和归因 |
| [ai-director](#ai-director--ai-编导师傅) | 按专业编导标准诊断、改写、评分短视频内容 |
| [benchmark-radar](#benchmark-radar--对标雷达) | 搜索和蒸馏对标账号,沉淀低粉高赞样本库 |
| [content-planner](#content-planner--选题规划器) | 把账号定位翻译成系列结构和选题库 |
| [wisdom-distiller](#wisdom-distiller--智慧蒸馏器) | 把历史人物变成可复用的思维模型卡 |

> 前 5 个是成套设计的自媒体运营流水线:**定位 → 对标 → 编导 → 选题 → 诊断**,互相之间有协作引用;第 6 个是独立的思维工具。

---

## account-niche-finder · 账号定位分析

对话式的账号定位分析:通过 5-6 轮结构化对话盘点你的真实素材,分析你适合用 AI 做什么类型的内容账号(聚焦小红书图文 + 公众号),输出定位报告。

**能做**:把"我该做什么账号"这个无限大的问题收敛到 2-3 个最值得验证的方向,每个方向附最低成本验证方案;报告敢排序、敢裁决——包括"你现在不该开号"这种结论。五维评分 + 动态权重,时效敏感字段(平台政策、赛道热度)强制联网核实。

**不能做**:预判内容数据。没有人能保证你做哪个赛道能火,本 skill 的诚实边界是"收敛方向 + 最小成本验证",不是"算出答案"。

**核心方法论**:
- AI 生产形式,人供给内容——分析主线是你有什么 AI 替代不了的素材
- 证据 > 自评——用户对自己的评估普遍不准,行为证据永远权重更高
- 向往与素材冲突是主战场——拆向往(桥接/转化/戳破),不选边站

**什么时候用**:
- "我想用 AI 做个账号,不知道做什么方向,帮我分析下"
- "我想做自媒体,纠结选什么赛道"
- "我适合做什么类型的内容账号"

约 15-20 分钟、5-6 轮对话后得到报告(含 `examples/` 里的模拟对话与示例报告参考)。

## account-doctor · 账号诊断医生

用真实数据给抖音/小红书账号做体检、归因和下一步动作建议。

**能做**:三步诊断——① 体检表(赞粉比、完播率等客观指标对照基准)→ ② 软限流自检(对照官方红线 + MCN SOP)→ ③ 三层归因(表层症状 → 内容层 → 账号层),最后给出下一步动作。坚持"缺数据先要数据,绝不凭空诊断"。

**不能做**:替代平台内部数据。诊断质量取决于你提供的后台数据完整度。

**什么时候用**:
- "为什么没流量""没播放""是不是被限流"
- "帮我看看号""账号诊断""复盘""数据不好怎么办"
- "涨粉慢""掉粉""断更了""要不要重新起号"
- 直接发账号主页链接、粉丝/播放/点赞数据或后台截图

## ai-director · AI 编导师傅

融合四位在营创作者四流派方法论(头套编导派 / 操盘手变现派 / 小厂训练派 / 特稿叙事派),诊断、改写、评分短视频内容。

**能做**:诊断/改写视频标题、口播稿、选题;按编导标准打分;设计系列栏目和账号内容规划。内置 16 条作品全量蒸馏的《编导方法论手册》:2026 平台风向(收藏/推荐/追更/社区四大互动指标)、选题共情半径公式、信息密度标准、爆款结构,可直接当评分标准。

**什么时候用**:
- "这条文案行不行""帮我改标题""这条能打几分"
- "怎么选题""怎么选赛道""怎么变现""什么是钩子""信息密度"
- "按编导标准帮我写一条口播稿""帮我设计一个系列栏目"

## benchmark-radar · 对标雷达

搜索、筛选和蒸馏对标账号,把"低粉高赞"样本沉淀进对标库。

**能做**:按赛道搜索候选账号 → 抓主页数据(粉丝/获赞/作品数/简介)→ 筛选低粉高赞样本 → 蒸馏爆款文案与账号结构入对标库,为定位报告补市场数据。附《抓取配方》:2026-10 实测过的抖音网页版浏览器自动化代码(4 账号、40+ 页面验证)。

**依赖与降级**:宿主 agent 具备浏览器自动化能力(如 browser-use)时全自动;没有时降级为手动截图/口述数据路径。平台改版后选择器可能需要小修。

**什么时候用**:
- "找对标""对标账号""拆解同行""这个赛道谁做得好"
- "竞品分析""赛道调研""有没有账号参考"
- "帮建一个 XX 赛道的样本库"

## content-planner · 选题规划器

把账号定位翻译成可执行的系列结构与选题库。

**能做**:承接定位报告,产出系列/栏目设计 + 选题库 + 内容排期;交付前过"选题硬规"自检(共情半径、链接人数、可执行性)。

**什么时候用**:
- "帮我出 20 个选题""设计 3 个系列""栏目怎么设计"
- "下个月发什么""做内容日历""更新计划"
- "我拿到定位报告了,帮我落地成内容"

## wisdom-distiller · 智慧蒸馏器

把任意历史人物蒸馏成可复用的「智慧模型卡」。

**能做**:提取人物的世界观内核、决策启发式、思维盲区、关键史实与经核实的原文金句,沉淀为结构化档案(`distilled/<人物名>.md`);之后可加载档案,用该人物的思维框架分析现代问题。

**什么时候用**:
- "蒸馏一下王阳明""帮我做一张曾国藩的智慧卡片"
- "王阳明会怎么处理我的这个困境""XX 会怎么看这件事"
- "用孙子兵法的思路帮我分析这个竞争局面"

## 安装

| Agent | 安装位置 | 触发方式 |
|---|---|---|
| ZCode | `~/.agents/skills/` 或 `~/.zcode/skills/` | 自动触发 |
| Claude Code | `~/.claude/skills/` 或 `.agents/skills/` | 自动触发 |
| Codex CLI | `~/.codex/skills/` | 自动触发 |
| 其他 agent / 网页对话助手 | 任意位置 | 手动:把 SKILL.md 作为指令发给模型 |

### 方式一:命令行安装(可只装一个)

```bash
git clone https://github.com/GoodnightXu2002/skills.git
cp -r skills/account-doctor ~/.agents/skills/   # 换成任意 skill 名和上表对应目录
rm -rf skills                                   # 清理临时 clone
```

想装多个就把 `cp -r` 那行重复几次。建议自媒体 5 件套(account-niche-finder / account-doctor / ai-director / benchmark-radar / content-planner)整包装,互相之间有协作引用。

### 方式二:转发给 coding agent 一键安装

把上面的安装命令和安装表一起发给任意 coding agent(ZCode / Claude Code / Codex),说"把这个 skill 装到你能识别的 skills 目录",它会自己完成。

### 方式三:网页直接下载

打开本仓库页面 → 绿色 **Code** 按钮 → **Download ZIP** → 解压后把想要的 skill 文件夹放进上表对应目录。

### 没有 skills 机制的 agent 也能用

每个 skill 的 `SKILL.md` 本身就是完整的执行指令:把 `SKILL.md` 连同 `references/` 下的知识库文件一起发给任何 LLM 对话助手,让它按流程执行即可——只是没有自动触发与跨会话复用。

## 使用

安装后新开会话,直接说需求即可自动触发(触发语句见上面各 skill 的"什么时候用")。例如:

- 装了 account-niche-finder:"我想做自媒体,纠结选什么赛道,帮我分析下"
- 装了 account-doctor:发一个抖音主页链接,说"帮我看看这个号还有救吗"
- 装了 ai-director:贴一条口播稿,说"按编导标准给这条打分并改写"
- 装了 wisdom-distiller:"蒸馏一下苏东坡,然后用他的心态分析我的裁员困境"
