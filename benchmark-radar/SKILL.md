# 对标雷达

技能包的市场数据层。产出两样东西：**对标卡**（单个账号的蒸馏档案）和**校准基准**（赛道级赞粉比/爆款率分布，供 account-doctor 用）。

## 工作流程

1. **锁定赛道关键词**（1-3 个，和用户确认或从定位报告取）。
2. **搜索候选**：抖音网页版搜索关键词（浏览器自动化），收集用户卡片（主页链接 + 昵称），一次收集 4-6 个候选。
3. **筛选标准**：逐个访问主页取真实数据（粉丝/获赞/作品数/简介），优先保留：
   - **低粉高赞样本**：累计赞粉比 ≥3，或单条爆款赞 > 粉丝数的 30%——这类账号的方法论最新鲜、可复制性最强；
   - 搭配 1 个大盘账号（粉丝量级明显高于其余）当赛道天花板参照；
   - 剔除纯搬运号、停更号（近 60 天无更新）。
4. **抓内容**：每个入选账号抓 4-8 条视频（置顶 + 最近）的"章节要点"（抖音 AI 生成的内容摘要），抓取配方见 `references/抓取配方.md`。
5. **蒸馏成对标卡**（模板见对标库 `template-对标卡.md`）：基本盘 / 人设与记忆点 / 内容配方 / 钩子库 / 系列结构 / 变现痕迹 / 可移植点×3 / 不适用点×1。
6. **入库**：写到工作区 `对标库/<赛道>/<账号名>.md`，更新 `对标库/_index.md` 的索引表及其「校准-基准」一节的赞粉比分布。
7. **回流**：诊断（account-doctor）需要基准时从这里取；生产（ai-director）做同类内容时引用对标卡的可移植点。

## 蒸馏纪律

- 只记录公开可见信息（主页、作品、AI 章节要点），不臆测未公开数据。
- 对标卡里"可移植点"必须是**结构与角度**（选题逻辑、系列结构、钩子角度），不得复制原文表达。
- 每个对标卡标注抓取日期——账号数据会过期，三个月前的卡视为待更新。

## 与其他技能的协作

- content-planner 出选题库前 → 可先查对标库找同赛道已验证选题角度。
- account-doctor 的基准表 → 由本技能的校准文件供数，样本量随入库增长。
